# Require Per-Run Provider Consent and Explicit Deletion

**Status:** The provider terms-review and disabled-until-review prerequisites are superseded by [ADR 0009](0009-configured-external-providers-with-per-run-consent.md). The local Crossref and Unpaywall configuration decision remains in [ADR 0006](0006-reviewed-provider-options-in-local-default-configuration.md). All per-run consent, payload-minimization, and deletion requirements remain.

Every provider must have a technically classified trust boundary and declared outbound payload categories before it can be enabled; unclassified boundaries and unclassifiable data flows remain unavailable. Provider terms review is not an enablement prerequisite: when an external provider is configured, disclose known retention/deletion terms or clearly state when those details are unknown. External providers may receive only the minimum necessary content with explicit per-provider, per-Analysis-Run consent for stable, disclosed data categories. V1 retains local document data until the user explicitly deletes it, with no automatic expiry. Deletion first tombstones the document and invalidates pending work; workers check the tombstone before starting new provider calls and before committing results. Deletion removes document-scoped content and derived results, including per-run consent/configuration snapshots, while shared assets remain only if another non-deleted document/run references them. Local deletion cannot retract content already sent to a provider, so provider retention/deletion limitations must be disclosed. This favors user control and predictable local retention over implicit external sharing or surprising automatic data loss.
