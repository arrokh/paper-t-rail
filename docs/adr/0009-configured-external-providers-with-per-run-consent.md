# Make Configured External Providers Selectable With Per-Run Consent

**Status:** Accepted

Provider-level terms review and an approval rubric are not prerequisites for offering an implemented external provider: required configuration or credentials make it selectable, and unknown retention/deletion details are disclosed as uncertainty rather than used as a gate. Keep each provider's actual trust boundary and outbound data categories explicit, keep credentials server-side, and require explicit per-provider, per-Analysis-Run consent for every external payload. API requests that omit provider choices use safe local/recorded defaults; the web new-run form may preselect configured Crossref and Unpaywall as editable preferences, but leaves all consent categories unchecked and sends no external data until the user explicitly approves them. Jev remains a non-default, explicit choice. A technically unknown boundary or undeclared payload remains unavailable because the system cannot classify its data flow or obtain meaningful consent. The immutable Analysis Run also stores the exact retention disclosure shown at consent time alongside the selected provider and authorized data categories; the disclosure is resolved server-side, not supplied or altered by the client. This favors user choice and low-friction experimentation while preserving visibility, historical explainability, and control over each external data transfer. This supersedes only provider terms-review and `enablementReviewed` prerequisites in ADRs 0003 and 0006; per-run consent, payload minimization, and deletion requirements remain. The implementation is tracked in [issue #69](https://github.com/arrokh/paper-t-rail/issues/69).
