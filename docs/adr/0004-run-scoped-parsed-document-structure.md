# Persist Parsed Document Structure Per Analysis Run

GROBID output is persisted under its `Analysis Run`, not shared by `Source Document`. Keep the exact raw TEI response in private object storage at a run-scoped, content-hash-keyed path and persist that key with the parsed records. Every run pins its parser identity/version and claim-extractor configuration, and re-analysis must preserve earlier results even if either implementation changes. Parsed structures and extracted Atomic Claims therefore store the run's source SHA-256, parser provenance, normalized text, sections, Citation Contexts, Citation Occurrences, Bibliography Entries, occurrence-to-entry targets, Atomic Claims with source spans, and inferred claim-to-target links as immutable run-scoped data.

The normalized source text is the whitespace-normalized text of the GROBID body sections in order, with one newline between sections and between paragraphs in a section. Section, citation, and claim spans are zero-based, end-exclusive UTF-16 code-unit offsets into that text, matching the Kotlin and browser string-indexing convention. GROBID TEI's citation-callout/reference links supply target identities. Context segmentation recognizes semicolons and explicit contrastive/subordinating connectors as clause boundaries; when no such boundary is reliable, markers stay within their containing sentence and the fallback kind is recorded. Every extracted claim links to every Citation Target in its own Citation Context; composite database constraints prevent cross-context links, and the association is labeled inferred/provisional.

The adapter explicitly submits `consolidateHeader=0` and `consolidateCitations=0` on every request. The default GROBID service runs on the private Compose network, and configured GROBID endpoints are restricted to localhost or trusted private-network addresses. GROBID bibliographic consolidation remains disabled. Separately, issue #7's reference resolver may send only the minimum parsed bibliography metadata to a selected scholarly-metadata provider when that external provider is explicitly enabled and the Analysis Run has consented to every payload category. Resolution outcomes are stored separately as immutable run-scoped records; read models may project their status without mutating parser-owned records.

The run is marked `PARSED`, not `COMPLETED`, after parsed source structure, Atomic Claims, inferred target links, bibliography-resolution outcomes, and eligible Cited Paper Evidence Passage retrieval are ready. Semantic Evidence Judgements and final Claim–Paper Verification have not run, and `Analysis Run` status `COMPLETED` remains reserved for a finished full Evidence Coverage Report. This keeps each run reproducible, makes every displayed source span auditable against stored normalized text, and prevents later parser, extractor, or resolver runs from rewriting earlier results.
