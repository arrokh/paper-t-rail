# V1 Provider Boundary and Retention Matrix

**Information snapshot:** 2026-09-24. This is an informational implementation aid, not legal advice or an approval rubric. Provider privacy notices, service terms, model versions, and deployments can change. The linked sources summarize information available when captured; refreshing or verifying those sources is not a prerequisite to offering a configured integration. “Not stated” means the cited public material does not establish a usable retention/deletion guarantee; it does not mean zero retention.

**Implementation status:** ADR 0009's no-terms-review policy and issue #69's hosted Jev integration are implemented in this checkout. Jev is selectable only when valid server-side configuration is present; it remains external, non-default, and subject to exact per-run consent. The local contract and queue tests do not establish the live provider's availability or model quality.

## How to read this matrix

- **LOCAL** means inference/processing can stay inside the operator-controlled deployment. It does not mean local storage is ephemeral: Paper T-Rail retains local document data until explicit user deletion (ADR 0003).
- **EXTERNAL** means data leaves the operator-controlled deployment boundary; the endpoint may be operator-owned or third-party-operated. Open-source software is not automatically local.
- **UNREVIEWED** means the technical trust boundary or actual outbound payload cannot currently be classified. It remains unavailable until the integration declares those facts, because consent cannot cover an unknown data flow. Unknown or unverified retention terms alone do not make a provider `UNREVIEWED` or block a configured integration; disclose that uncertainty.
- The categories below name the **actual planned request payload categories** using the stable identifiers in the tech design. `provider_contact_email` identifies an operator contact address, not Source Document content; include it in the disclosure and consent when a provider requires or is configured to receive it. Do not send categories absent from the provider's declared mapping; add the mapping and require matching consent before sending them.
- Readiness is not consent. An implemented provider becomes offerable when its required configuration or credentials are present; no separate terms-review or approval-rubric gate is required. This never grants consent: every external provider still requires explicit, provider-specific, per-Analysis-Run consent for the exact declared payload categories before sending them. Show known retention/deletion information, or clearly say when it is unknown; neither a default nor a previous run's consent authorizes a later run.

## Calibration status and product policy

Human calibration and deployment-specific production approval are not product or release requirements. Calibration status remains `NOT_APPROVED`; this is informational, not a release blocker. Make no accuracy or calibrated-output claim, and label all non-mock System One judgements and final statuses uncalibrated. Until authentication exists, restrict app access to localhost or a trusted private network; retain per-run consent for any external-provider request; and provide a rollback path. Public exposure requires authentication. Issue #45 is closed as not planned. Calibration tooling and protocol documents are optional references, not release gates.

## Safe baseline profile

The canonical conservative deployment example is in [Provider Enablement Configuration, section 29](../paper-t-rail-tech-design.md#29-provider-enablement-configuration), with local defaults in [section 55](../paper-t-rail-tech-design.md#55-local-development-defaults). The conservative target-specific opt-out profile retains heuristic extraction, trusted local Ollama with deterministic feature-hash fallback, mock System One, self-hosted GROBID for Stage 01 with consolidation explicitly off, self-hosted Docling for new Stage 04 Cited Paper parsing, and recorded-fixture ports for metadata, graph, and OA discovery as selected defaults. Local Compose starts its trusted Ollama service. API requests without an embedding choice prefer the pinned `nomic-embed-text:v1.5` model when locally selectable; the web new-run form defaults to local feature-hash. Laya starts automatically with `make dev` unless explicitly disabled; its artifacts are downloaded and digest-verified into a persistent volume, and its sidecar is isolated from public ports and outbound networking. `make laya-up` remains available for separate startup/recreation. New local runs select Laya when it is selectable, otherwise missing Laya configuration resolves to mock. Selected eligible passages produce persisted raw uncalibrated judgements; `.env.example`, base Spring configuration, and Compose default `SYSTEM_ONE_AGGREGATION_ENABLED=true`, enabling experimental aggregation with the documented baseline thresholds. Set it to `false` to keep final statuses `NOT_RUN`. Per #45, the production Spring profile defaults Laya enabled/selected and aggregation enabled; this does not calibrate outputs. Human calibration and deployment-specific approval are not product requirements; this does not establish accuracy. The application preference defaults to Laya, but missing configuration resolves omitted selections to mock. The conservative example remains an explicit opt-out for targets choosing not to use experimental Laya. Calibration is not required for release; this does not constitute a calibration or accuracy finding. All results remain uncalibrated. The repository's local application configuration additionally offers Crossref and Unpaywall options for consent-flow testing; their terms summaries and contact values are informational configuration, not approval gates. Jev can also be selected when its server-side key is configured, but it remains non-default and requires explicit per-run consent. The fixture set must cover successful and unresolved metadata matches, OA locations/access statuses, parser outputs, and a representative end-to-end paper so the pipeline can run without remote credentials or network access.

A configuration switch does not collect consent. Every external-provider Analysis Run requires disclosure of the provider and exact data categories plus explicit consent for that provider and run. Show known retention/deletion limitations or state when they are unknown; missing or unverified terms are not an enablement gate. Local deletion cannot retract content already sent externally (ADR 0003 and ADR 0009).
