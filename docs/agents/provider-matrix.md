# V1 Provider Boundary and Retention Matrix

**Review recorded:** 2026-09-24. This is an implementation decision aid, not legal advice. Provider privacy notices, service terms, model versions, and deployment choices can change; re-check the linked primary sources before enabling a provider and record the reviewed product/version and date. “Not stated” means the cited public material does not establish a usable retention/deletion guarantee; it does not mean zero retention.

## How to read this matrix

- **LOCAL** means inference/processing can stay inside the operator-controlled deployment. It does not mean local storage is ephemeral: Paper T-Rail retains local document data until explicit user deletion (ADR 0003).
- **EXTERNAL** means data leaves the operator-controlled deployment boundary; the endpoint may be operator-owned or third-party-operated. Open-source software is not automatically local.
- **UNREVIEWED** means the exact provider/product/deployment or its terms are not sufficiently specified to approve. Treat it as disabled.
- The categories below name the **actual planned request payload categories** using the stable identifiers in the tech design. `provider_contact_email` identifies an operator contact address, not Source Document content; include it in disclosure/consent when a provider requires or is configured to receive it. Do not send categories not named for that provider without updating this review and collecting matching consent.
- Readiness is not consent. Classification and an administrative enablement review establish only that an integration may be offered. Every external provider still requires explicit, provider-specific, per-Analysis-Run consent for the exact disclosed categories before a request containing those categories is sent. Neither a default nor a previous run's consent grants consent for a later run.

## Safe baseline profile

The canonical conservative deployment example is in [Provider Enablement Configuration, section 29](../paper-t-rail-tech-design.md#29-provider-enablement-configuration), with local defaults in [section 55](../paper-t-rail-tech-design.md#55-local-development-defaults). Both retain heuristic extraction, the deterministic local feature-hash vectorizer, mock System One, self-hosted GROBID with consolidation explicitly off, and recorded-fixture ports for metadata, graph, and OA discovery as selected defaults. The repository's local application configuration additionally offers reviewed Crossref and Unpaywall options for consent-flow testing; deployments must review current terms, provide deployment-specific disclosures/contact values, or disable them. The fixture set must cover successful and unresolved metadata matches, OA locations/access statuses, parser outputs, and a representative end-to-end paper so the pipeline can run without remote credentials or network access.

A configuration switch does not collect consent. Every external-provider Analysis Run requires disclosure of the provider, exact data categories, and provider retention/deletion limitations, plus explicit consent for that provider and run. Local deletion cannot retract content already sent externally (ADR 0003).
